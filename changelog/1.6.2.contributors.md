- #10, migration 066: several PSN accounts per person (up to three). `/panel` has one row per platform (`views/keyboards.py::_platform_row`) and a screen per platform (`views/panel.py::render_account_menu`).
- Login rows: `panel-login-row` per platform, `visibility_status_text(..., with_time=False)`; ❗ on a Steam/PSN button while `achievements_visible` is false.
- Profile links: `app_settings['show_profile_links']` (`SHOW_LINKS_KEY`, default on), toggled in /admin → global settings; `user_settings.show_profile_links` is no longer read and `/api/mini/settings` no longer accepts it.
- Account-flow steps edit their own message and end in buttons (`views/keyboards.py::buttons`, `panel_button`, `back_to_panel_button`); the timezone picker opened from /panel uses the `ptz:` prefix and returns to the panel.
- Panel and account screens go out with `parse_mode=HTML` — the views escape every name they interpolate.
- Reset cooldowns, migrations 067/068: one deletion counts once per platform for the person and once per account (`platform_cooldown_accounts`), so each PSN account is protected on its own; the person's PSN side counts re-links (`free_relinks` = PSN accounts held at the deletion, `relinks` spent via `note_platform_relink` in `link_platform_account`).
- Panel and account screens go out with `parse_mode=HTML`; the panel view escapes every name it interpolates. The rarity mode is a carousel (`panel:rarity` cycles `next_rarity_mode`); the picker screen is gone.

- #133/#139/#140: `settings_button()` in groups, `/promo` only, the four-command DM menu and `private_help_text()`.

## Backfill status

- `bot/handlers/backfill.py`: `run_xbox` / `run_steam` / `run_psn` own one status message, redrawn at most every `PROGRESS_INTERVAL` (5 s), ending as the result or a retry (`bf:xbox`, `bf:steam`, `bf:psn:<account_id>`). Each fetcher's `backfill(..., progress=)` reports `(done, total, found)` (`Progress` in `services/psn/achievements.py`); Xbox counts three steps, not games.

## Syncing and descriptions

- #91/#92: Xbox 360 history from contract 1 `/achievements` and `/history/titles`, topped up once at startup (`Fetcher.fill_x360_gaps_once`).
- #127, migration 065: a Russian description is trusted only with a `description_source`, and only when it reads as Russian (`util.looks_russian`); non-Cyrillic Russian sides are dropped and re-queued.
- Translation goes out in calls of 40 descriptions (`translate/client.py::_BATCH_SIZE`), not one per game: a 1075-achievement game's reply could not fit `max_tokens`. A reply cut off at `max_tokens`, or with a line missing or added, is dropped instead of being matched by position.
- PSN pacing: psnawp's own limiter, one request every 2 s per client (`psn/client.py::REQUEST_RATE`; the library default is 3 s). Its bucket is per process.
- #132: Steam secret descriptions from the profile page (`steam/client.py::community_descriptions`, `Steam_Language` cookie), at poll time and by the description walker.

## Steam guides and patches

- Migration `069_steam_guides_patches.sql`: `titles.steam_appid*`/`tips_checked_at`, `title_achievements.tip_*`, `steam_apps`, `game_patches`; repo mixin `bot/db/repo/_steam.py`.
- `bot/services/steam_extras.py` fills a game (appid, tips, patches) after `ensure_title_match` in the three fetchers, in a background task; `bot/poller/patch_refresh.py` re-reads played games' patches (`patch_refresh_hours`). `steam_guides.py` / `steam_news.py` are network only.
- Mini API: `GET /api/mini/games/{platform}/{title_id}/guides` and `/patches` read the database. Webapp: `GameTabBar.tsx` (sliding, looping tab row), `PatchNotes.tsx`, tips in `GameAchievementRow.tsx`, `RichText.tsx` (links, videos, pictures, tables), `game-cache.ts` (what a game last showed, for the session).
- **Which lines are a tip is Haiku's call, never rules or word lists** (owner, 2026-10-01): `bot/services/translate/guide_tips.py` cuts a guide into blocks at the lines that are exactly an achievement's name and asks the model, per block, for line numbers only (`block § first § last`, split on `§`, no JSON); the tip is those lines copied (`steam_guides.tip_from_lines`). A guide naming fewer than three achievements, one in another language (the model answers `SKIP`), and PlayStation's platinum (`title_achievement_names`) are passed over. `SteamExtras._fill_tips` reads guides lazily (`guides_of(..., stop_when=)`) and stops at the first one that fills half of the game's achievements. Needs the Anthropic key; none means no tips and nothing stamped.
- Migration `070_title_guide_reads.sql`: `title_guide_reads (title_id, guide_id, fingerprint, found)`. The model is asked about a guide only when its fingerprint (guide lines + the game's achievements) differs from last time; an unchanged guide gives back its stored tips (`repo.tips_from_guide`), one that gave nothing is not asked again. `translate/client.py::ask_model` is the one place the model is called for this.
- A visit reads tips only for a game never worked out; a set a month old is re-read by `poller/patch_refresh.py` (`TIPS_REFRESH_DAYS`), one game a tick. Steam backs off 90 s, doubling to 15 min, on repeated 429 (`steam_guides._refusals`).
- Webapp: `EmptyState` (`components/shared/lib/empty-state/`) for an empty month; the Day/Month filter's `.segment button` rules moved to `Toggle.css`; the account icons are back in `PlatformCard.tsx` (the "Posting" button and its plumbing are gone from the Mini App; `setAccountPublishes` stays in the API client).
