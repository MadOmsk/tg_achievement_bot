# 1.1.0 — notes for contributors

What changed about *working here*, as opposed to what changed for the chat
(see `1.1.0.en.md` for that). If you last read this codebase before
17 September 2026, these are the things that will surprise you.

`CLAUDE.md` is the source of truth for all of it and was updated with each
change; this file is the map of what moved.

## A person and an account are different things (#52)

The biggest change, and the one most code touches.

`users` holds the Telegram identity and nothing else. A platform account is a
row in **`accounts`** `(platform, external_id, display_name, secondary_name,
gamerscore, …)`, and **`account_links`** `(tg_id, platform, external_id,
is_active)` says who holds it now and who held it before.

`seen_achievements` is keyed by **the account that earned the row**, so "this
person's achievements" is a join, not a column. Write it once:

```python
from bot.db.repo._sql import OWNED_BY_PERSON, OWNED_BY_PERSON_EXISTS
```

`db/repo/_sql.py` is new and exists precisely because an answer copied into
twenty queries eventually disagrees with itself. It now holds the ownership
join, the Xbox account join, the localized-name columns, the date rule and
the rarity join.

Two consequences are intentional: an account nobody holds is invisible
everywhere, and an account that changes hands takes its history with it —
retroactively, so a summary already posted recomputes differently.

`User` still exposes `xuid`/`gamertag`/`gamerscore` under their old names,
read through the `XBOX_ACCOUNT` join, so the ~70 Xbox call sites did not have
to change at once.

## Layout lives in `bot/views/` (#63), and mockups are rendered

Handlers route and act; they no longer build text or keyboards. Every screen
has a module under `bot/views/`, a view renders and never sends, and it
returns a `Screen` (text, keyboard, photo).

`docs/ui/` is **gone**. It was three hand-kept mockup files plus a script to
catch them drifting. To look at a screen, draw it:

```bash
python scripts/render_screen.py --list
python scripts/render_screen.py panel --locale en
python scripts/render_screen.py admin-user-card --send
```

Point `DB_PATH` at a copy of production to render against real data. Two live
bugs this release were found only by rendering a screen after deploying —
including one where 921 tests were green and none of them had ever looked at
the number on screen. `tests/test_render_screen.py` now sweeps every screen
the script knows, which is a weak assertion (it builds) covering the one
thing nothing else did (the call still type-checks at runtime).

## Two list families

- **`views/lists.py`** — lists made of text. `Listing` (rows, optional header
  and total, quoted or plain) and the shared games row.
- **`views/inline_lists.py`** — lists made of buttons. `InlineListing`,
  `button_rows`, `paginate`, one `page_nav`.

`services/tables.py` is gone; so is the monospace `<pre>` table it rendered.

The games list is **one template with three scopes** — `/stats`,
`/summary_day`, `/summary_month` — sharing the query
(`repo.users_games_achievements`), the row, and the mapping between them
(`views/lists.py::games_listing`). Adding a fourth scope is another set of
arguments, not another screen.

`TopGame` and `ChatTopGame` are replaced by `GameAchievements`;
`repo.user_games` and `repo.chat_top_games` by
`repo.users_games_achievements(tg_ids, since, …)`.

## One date rule, in one place (#69)

`COALESCE(unlocked_at, created_at)` was in sixteen queries and lied in one
case. Use the fragments:

```python
from bot.db.repo._sql import earned_at, earned_date_is_real, earned_since
```

- a row the platform dated is placed by that date;
- an undated row a **live poll** found is placed by when the bot saw it;
- an undated row an **import** brought in is ancient and falls outside every
  window.

`is_backfill` is **not** a filter for this. It means "do not publish", not
"did not happen" — filtering on it was tried and threw away imports the
platform had dated, emptying a person's `/stats`. Three readers keep plain
`COALESCE` deliberately and say why in place.

## Rarity is a fact about the achievement

`seen_achievements.rarity_percent` is a snapshot: written once with
`INSERT OR IGNORE`, never updated, and on Xbox usually absent — rarity rides
only on contract 4, while backfill uses contract 2.

Read rarity through `rarity()` / `rarity_cache_join()`, which prefer
**`achievement_rarity_cache`** and fall back to the row. Every platform's
ordinary poll writes to it; `poller/rarity_backfill.py` fills the Xbox
history, and `scripts/backfill_rarity.py` does the same walk in one sitting.

`checked_at` orders the refresh queue and is not an expiry — nothing is
hidden for being stale.

## Locale is per context, never per process (#48, #61)

A group renders in `chat_settings.locale`, a DM in `user_settings.locale`.
Outside aiogram's own update handling the locale is an **explicit argument**:
`gettext(module, key, locale=...)` or `translator(module, locale)` bound at
the top of a render. Deliberately not a `ContextVar` — the publisher and the
summary both loop over chats.

`ru` and `en` both ship complete, and `tests/test_locale_parity.py` enforces
same files, same keys, same `$variables`. Plural forms select in Fluent on
`$count`; never compute a form in Python.

Names and descriptions live in shared caches keyed
`(platform, title_id, achievement_id)` and are what a published message
renders from — the row is only the fallback.

## Nothing sent may fail for being too long (#68)

`services/message_limits.py` is a request middleware on the Bot's pipeline
(the seam `message_log.py` already uses). It trims any outgoing text to its
own maximum — 4096 / 1024 / 200 — keyed off which fields a method has, so a
send this bot does not make yet is covered when it is added. HTML is cut only
between tokens and reclosed, because a naive cut trades
`message is too long` for `can't parse entities`.

You should not need to think about length in a view. If you find yourself
capping a list by row count for that reason, don't — the limit is in
characters.

## Versioning, and a database from the future (#56)

`A.B.C.D` in `bot/version.py`, rendered in `/help` and logged at startup.
`B` says which line of work a build is from (`0` is the trunk), `C` counts
commits since the merge base, `D` is the newest migration shipped.

**`Database.connect()` refuses to start when the database has migrations the
code does not ship** (`SchemaTooNewError`). Behind is an upgrade; ahead is
the 14 September outage, where a script run from a working branch migrated
production's database and the production bot crashed on tables it had never
heard of.

Two related rules now in `CLAUDE.md`, both learned the hard way:

- a **brand-new** database is baselined, not migrated — `schema.sql` already
  produced the result;
- a migration adding a column `schema.sql` already created is **not** an
  error, and `_apply_one` swallows exactly `duplicate column name`;
- **rehearse a migration against a copy of production before deploying it.**
  That afternoon caught three deploy-breaking faults, two of which no test
  could have: they only exist on a database with production's history.

## Smaller things worth knowing

- `bot/db/repo/` is a package of mixins, not one file. `from bot.db.repo
  import Repo, User, …` still works; see its `__init__.py` for the map.
- New pollers: `rarity_backfill`, `steam_localization`, `avatars`,
  `psn_presence`. All follow the same shape — a few items a tick, a
  process-lifetime set of things nothing could answer for, never a hot loop.
- New services: `presence_view` (one answer to "where is this person"),
  `credential_health` (a death is confirmed before it is announced, and
  recovery is announced too), `relink`, `avatars`, `message_limits`,
  `admin_settings` (the numeric-settings registry).
- `handlers/delivery.py` and `handlers/awaiting.py` split the two things
  handlers legitimately still own: sending, and "who is typing what".
- Every one-off script that touches Xbox needs the bot stopped — Microsoft
  rotates a per-user refresh token and invalidates the previous one, and the
  guard against that is an in-process `asyncio.Lock`.
  `scripts/backfill_rarity.py` takes the bot's own single-instance lock and
  refuses to start rather than trusting the operator to remember; the older
  scripts only say so in a docstring.
- Anything extracted from a database goes in `backups/`, and a dump may never
  hold a decrypted secret.
