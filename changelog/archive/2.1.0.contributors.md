# 2.1.0 — notes for contributors

## Version

- A minor release: `TRUNK_LINE` 0 → 1, tagged `v2.1.0`; migrations 133–137 (D is `137`); no new dependency.
- Rehearse 133–137 on a copy of production before the merge into `main` (CLAUDE.md, Bring-up and migrations).

## Mini App

- The season pass (#226): a pass a month built by the super-admin in the Mini App — themes, game and code prizes (`pass_items`, `pass_item_codes`, 133, 135, 136), drafts published at once, levels reached told once a month (`pass_reached`, 134; `pass_level`, `pass_reward` notices), a month's name (`pass_seasons`, 137). Codes go one to a person in one statement; draft pictures only through the editor's signed address. See CLAUDE.md, the season pass.
- An Xbox list is split into the main game and its add-ons (`repo.earned_groups`); the month's games newest first (`users_games_achievements(order="recent")`).

- `webapp/src/ui/Face.tsx::faceSrc`: inside Telegram a face is fetched with Init Data (`fetchAvatarBlob`) and kept as an object URL; in a browser the session cookie signs the plain address. A bare `<img>` carries no header and was refused with 401.

## Bot

- `services/game_art.py`: a game's poster, hero and header are served from `/api/mini/art/{sig}?u=<store address>`, signed with a key derived from `FERNET_KEY`, fetched only from the stores' picture hosts, shrunk like an achievement icon (1280 px) and kept under `covers/art/` by the address's hash. `game_page.art_of` hands these out; `store_art` keeps the raw addresses. The octopus keeps a game's art as it assembles it (`game_art.ensure`).
- `services/media.py`, `MEDIA_DIR`: the games database's pictures (achievement icons, covers, art) in one directory shared by prod and the test server; unset, they stay under `data/`. `images.write` now writes aside and renames.
- `services/x360_frame.py`: a 360 game's portrait box art loses its header (top 13%), the 1080 px square its green bar (left 190 px) — on a 360 list's cover download (`covers.download(platform=)`) and on a poster that stands in from a 360 list's icon (marked `#x360`). `scripts/strip_x360_frames.py` cuts what was kept before, with no request.

## Operations

- `scripts/xbox-deploy.sh`: every run takes `/run/xbox-deploy.lock`; a deploy stops the bot, runs `scripts.catalog_files import` (labels and weights from `catalog/`), then starts and verifies it — a failed import starts the bot and fails the deploy. A bot this script stopped is started again on any failure.
- `xbox-deploy catalog [--dry-run]`, run by hand on the VPS (no workflow: a one-off): export from test.db with the test bot stopped for a moment, then `catalog_transfer import` and `catalog_files import` into bot.db with prod stopped; the octopus's queue is not carried (`catalog_transfer export --except`; each server's own work); refused while the two databases' migrations differ; the dry run rehearses on a copy of bot.db. The two newest `bot-pre-catalog-*.db` are kept.
- The deploy that installs this script still runs the previous one to its end, so the first deploy after it brings `catalog/` in only from the next.
- CI runs `shellcheck scripts/xbox-deploy.sh`.
- Prod: set `MEDIA_DIR=/srv/unlocked-media` in `.env` with this release (the test server already has it); after a day, remove the old `data/achievements` and `data/covers`.
