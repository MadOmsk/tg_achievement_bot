## HLTB automatic title matching (#131)

- `bot/services/hltb_match.py` — pure scoring, no DB/network access, tested in isolation via `tests/test_hltb_match.py`. Given a `GameIdentity` (every name the game goes by, its platform, its known release platforms, the year anyone here first earned something in it) and a list of HLTB search candidates, it scores each one: name similarity (normalized + a *cored* variant with edition/platform tails cut — "- Definitive Edition", "(PC)", "Reloaded Edition" — at a small discount so the exact name still wins over the cored one), a differing number treated as a different game, a small penalty for a DLC/mod entry or a release year that predates when anyone here could have earned anything, popularity only breaking a near-tie. A Steam game is settled outright by the appid HLTB's own page lists for a candidate.
- `bot/services/hltb.py::ensure_title_match` is the lazy trigger — a no-op once `titles.hltb_id` is set or `hltb_attempts` hits 3. Called from `poller/fetcher.py`, `poller/steam_fetcher.py`, `poller/psn_fetcher.py` right after a game's first new achievement publishes (never during backfill — backfill never publishes), and again from `bot/web/mini_api.py::handle_game_hltb` if a game still has no match when the Mini App asks.
- `bot/db/repo/_admin.py`: `title_hltb_match_row` (what the matcher needs to try), `record_hltb_match`, `give_up_hltb_match` (a placeholder name like "Unknown" skips straight past the three retries), `title_hltb_match` (the stored answer, for reading back).
- Verified by hand against ~200 real games from a production-shaped library: no wrong match, only occasional correct refusals (a placeholder platform name, an ambiguous subtitle with no clear winner). Full test suite in `tests/test_hltb_match.py`.

## Mini App

- `GET /api/mini/games/{platform}/{title_id}/hltb` is its own endpoint, deliberately not part of `handle_game_details`'s response: an unmatched game's first visit costs a few HLTB requests, and that must never delay the achievements the person actually opened the page for. `TitleSheet.tsx` fires both requests independently; the "About" tab fills in whenever its own answers, with its own skeleton in the meantime.
- The game page's achievements list and the new "About" tab are two `SwiperSlide`s in one looping, swipeable `Swiper` (`effect="fade"` — a plain horizontal slide made the very different panel heights look like the outgoing panel's content was sliding into the next one). The tab bar is a small always-visible label row (`GameTabBar`), not an accordion — an accordion was tried first and read as its own separate interaction rather than "two views of the same page".
- Sticky blurred headers (`.page-head`) with `backdrop-filter` on Feed, Stats, and Settings; month chip placed directly in the header row.
- Games section on Home gains sort toggle (by recent activity or by achievement count for the month). Section counters for "Friends" and "Games".
- Avatar presence indicators streamlined to crisp green-tinted vector marks (`#3ee070`) without solid circular badges.

## Mini App chat entry points & notifications

- `bot/poller/publisher.py`: `Publisher` passes `reply_markup` generated via `mini_app_open_markup` to single achievement notifications and digests. Because Telegram Bot API does not support `InlineKeyboardMarkup` on media groups (`sendMediaGroup`), digests with `reply_markup` are delivered as a single-photo card (`send_photo`) with the full digest text in the caption, preserving the button. When no `reply_markup` is present, multi-item digests fall back to `send_media_group`.
- `bot/views/promo.py`: Dedicated module for pinnable promo messages (`promo_text` + `promo_keyboard`). Formatted with a concise first line for Telegram pin bar preview.
- `bot/handlers/chat.py` & `bot/handlers/admin.py`: `/promo` command and direct "📢 Отправить промо в чат" callback from admin chat cards.
