# Achievement Bot

Telegram-бот для игрового чата: публикует ачивки и трофеи, которые участники
получают на **Xbox, Steam и PlayStation Network**, ведёт статистику каждого и
работает вместе с Telegram Mini App. Некоммерческий проект для сообщества на
20–30 человек, у которого один администратор.

Правила, архитектура, текущее поведение и полное дерево файлов — в
[CLAUDE.md](CLAUDE.md) (на английском); прочитай его, прежде чем менять продукт или
архитектуру. Открытые задачи — в [Issues](https://github.com/MadOmsk/tg_achievement_bot/issues),
что изменилось в каждом релизе — в [changelog/](changelog/).

## Что умеет

**В групповом чате**
- Карточка на каждую новую ачивку: иконка, игра, версия, на которой играли,
  прогресс в игре (`47/50`), редкость, описание (у секретных — под спойлером).
  Несколько ачивок сразу собираются в один дайджест; антифлуд придерживает
  всплеск и присылает его позже одним сообщением.
- Каждый сам выбирает, что публиковать: все, только редкие или ничего; «редкие»
  считаются по порогу редкости конкретного чата.
- Итоги дня и месяца по расписанию, а также `/stats`, `/online`, `/recent`, `/who`,
  `/hltb` (время прохождения с HowLongToBeat) и меню настроек.

**В личке**
- Личная панель: подключение и отвязка аккаунтов (до трёх аккаунтов PSN),
  переключатель публикации для каждого аккаунта, часовой пояс, язык и выбор чатов
  для публикации — всё кнопками, в одном сообщении.
- Живой статус, пока бот читает историю аккаунта.

**Mini App** (`webapp/`) — лента, профили, клуб и страница каждой игры: ачивки с
прогрессом, время прохождения и описание с HowLongToBeat.

**Для администратора** — `/admin`: состояние общих ключей, сами ключи, лимиты,
чаты и их настройки, пользователи, исключения, очистка сообщений бота.

Бот говорит по-русски и по-английски: группа — на своём языке, личка — на языке
человека.

## Платформы

| | Как игрок подключается | Что должно быть открыто |
|---|---|---|
| **Xbox** (One, Series, PC, 360) | входит через Microsoft | ничего — бот работает под его входом |
| **Steam** | присылает ссылку на профиль | профиль и «Игровая информация» |
| **PSN** | присылает Online ID | трофеи видны «Всем» |

Для Steam и PSN у бота один общий доступ на всех: ключ Steam Web API и NPSSO
одного аккаунта PlayStation. Оба задаёт администратор в `/admin`.

## Что нужно до старта

1. **Токен Telegram-бота** от [@BotFather](https://t.me/BotFather) → `BOT_TOKEN`.
2. **Регистрация приложения на [portal.azure.com](https://portal.azure.com)** — без
   неё вход в Xbox не работает. Нужны scopes `XboxLive.signin
   XboxLive.offline_access` и redirect URI, совпадающий с `OAUTH_REDIRECT_URL`;
   регистрация даёт `AZURE_CLIENT_ID` и `AZURE_CLIENT_SECRET`.
3. **Домен с HTTPS** для `OAUTH_REDIRECT_URL` (например,
   `https://your-domain/auth/callback`). Microsoft не принимает ни `localhost`, ни
   `http://`. Для локальной работы подойдёт туннель (Cloudflare Tunnel сразу даёт
   `https://`), на сервере — nginx + Let's Encrypt.

## Настройки

`.env` (шаблон — [.env.example](.env.example)).

| Переменная | |
|---|---|
| `BOT_TOKEN`, `ADMIN_TG_IDS` | обязательны; `ADMIN_TG_IDS` — Telegram id администраторов через запятую |
| `AZURE_CLIENT_ID`, `AZURE_CLIENT_SECRET`, `OAUTH_REDIRECT_URL` | обязательны, для входа в Xbox |
| `FERNET_KEY` | обязателен; им шифруются все хранимые токены и ключи — сделай резервную копию |
| `STEAM_API_KEY`, `ANTHROPIC_API_KEY` | по желанию, только для первого запуска: дальше ключ хранится в базе и меняется в `/admin` |
| `MINI_APP_URL` | по желанию; пустое значение отключает кнопки Mini App |
| `DB_PATH`, `LOG_LEVEL`, интервалы опроса | по желанию |

Сгенерировать `FERNET_KEY`:

```bash
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

NPSSO для PSN в `.env` не кладут: его вводят в `/admin`, и перед сохранением бот
проверяет его настоящим запросом. Без ключа Steam или NPSSO эти платформы просто
недоступны, остальное работает.

## Anthropic и расходы

Через Claude Haiku (Anthropic API) бот переводит описания ачивок, которые платформа
даёт только на одном языке, и описания игр с HowLongToBeat. Каждый текст переводится
один раз и сохраняется. Без ключа ничего не ломается: текст показывается на том
языке, на котором пришёл.

У Anthropic есть только **месячный** лимит расходов, и задаётся он на workspace.
Заведи каждому окружению — проду, тестовому серверу, каждому разработчику — свой
workspace со своим ключом и лимитом. Тогда один неудачный тест не съест общий
бюджет, а на странице Usage видно, кто сколько потратил.

## Локальная разработка

```bash
git clone https://github.com/MadOmsk/tg_achievement_bot
cd tg_achievement_bot
python -m venv .venv
.venv\Scripts\pip install -e .[dev]
copy .env.example .env
```

`manage.ps1` запускает бота на твоей машине (на сервере это делает systemd):

```powershell
.\manage.ps1 start | stop | restart | status | logs [-Lines N]
.\manage.ps1 dashboard           # статус в реальном времени с горячими клавишами; то же открывает manage.bat
.\manage.ps1 start -Test         # второй экземпляр, из .env.test
.\manage.ps1 start -Test -Web    # плюс Mini App: Vite и туннель, MINI_APP_URL подставится сам
```

**Никогда не давай локальному боту `BOT_TOKEN` прода:** два процесса на одном
токене отбирают друг у друга сообщения из Telegram.

Mini App отдельно:

```bash
cd webapp
npm install
npm run dev      # vite
npm run build    # проверка типов + сборка
```

Тесты и линтер — ни один тест не ходит в настоящие платформы или Telegram:

```bash
pytest
ruff check . && ruff format --check .
```

## Ветки, серверы и релизы

| Ветка | Сервер | Обновляется |
|---|---|---|
| `dev` | машина разработчика | после каждого коммита (локальные git-хуки) |
| `prerelease` | тестовый сервер | CI на каждый push |
| `main` | прод | CI, когда в него сливают `prerelease` |

CI прогоняет тесты, обе проверки ruff и сборку Mini App и только потом деплоит:
`scripts/xbox-deploy.sh` делает резервную копию базы, обновляет код, перезапускает
бота и ждёт, пока он сообщит, что поднялся. В GitHub хранятся только SSH-ключ и
адрес сервера для деплоя — никогда `.env`, `FERNET_KEY`, база или ключи платформ.

**Релиз** — это: заметки в `changelog/` (на русском и английском, короткая выжимка
для анонса и заметки для разработчиков), короткое ревью, репетиция новых миграций на
копии прод-базы, затем слияние `prerelease` → `main` merge-коммитом. При запуске прод
объявляет новую версию в своих чатах со ссылкой на заметки.

Версия выглядит как `A.B.C.D` — архитектура, минорная линия, номер релиза, последняя
миграция — и видна в конце `/help`.

## Как участвовать

1. **Работай в своей ветке.** Она твоя: запускай из неё своего бота со своим
   `.env` и своими ключами (Anthropic в том числе) и пробуй что угодно.
2. **Готовое предлагай pull request'ом в `prerelease`** — никогда в `main`.
3. После слияния апдейт собирается и выкатывается на тестовый сервер.
   Администратор репозитория его тестирует и выпускает в прод (`prerelease` → `main`).

Что должно быть в pull request:
- что изменилось для игроков — в заметках **следующей** версии
  (`changelog/<A.B.C>.*`); уже выпущенную версию не правят;
- тексты для пользователей — только в `bot/locales/` (русский и английский, их
  одинаковость проверяет тест); код, комментарии, коммиты и issues — на английском;
- зелёные тесты и ruff; новый экран сначала согласован (`scripts/render_screen.py`
  рисует любой экран на настоящих данных и может прислать его администратору в
  личку);
- новые миграции — администратор репетирует их на копии прод-базы перед релизом.

Всё остальное — модель данных, особенности платформ, правила публикации — в
[CLAUDE.md](CLAUDE.md).
